# Практическая работа №6 — смарт-контракт управления доставкой

Проект реализует смарт-контракт на Solidity, который хранит сведения о доставках,
контролирует переходы между состояниями и ограничивает операции в зависимости от
роли пользователя. 
## Что реализовано

- модель доставки: `deliveryId`, `orderId`, `customer`, `courier`, `price`, `status`;
- состояния `Created`, `Accepted`, `InTransit`, `Delivered`, `Cancelled`;
- роли оператора, заказчика и назначенного курьера;
- создание доставки и получение данных по ID доставки или заказа;
- назначение курьера оператором;
- последовательный жизненный цикл `Created -> Accepted -> InTransit -> Delivered`;
- отмена заказчиком или оператором только до начала доставки;
- запрет прямого перехода `Created -> Delivered`;
- проверки через модификаторы и пользовательские ошибки Solidity;
- события `DeliveryCreated`, `CourierAssigned`, `DeliveryStatusChanged`;
- шесть автоматических unit-тестов для Remix.

## Структура проекта

```text
pr6/
├── contracts/
│   ├── DeliveryActor.sol
│   └── DeliveryManager.sol
├── tests/
│   └── DeliveryManager_test.sol
└── README.md
```

`DeliveryActor.sol` — только вспомогательный контракт для проверки разных адресов.
Разворачивать для демонстрации нужно именно `DeliveryManager`.

## Роли

| Роль | Кто это | Доступные действия |
|---|---|---|
| Оператор | аккаунт, развернувший контракт | создать доставку, назначить курьера, отменить доставку до начала перевозки |
| Заказчик | адрес, переданный в `createDelivery` | получить сведения, отменить доставку до состояния `InTransit` |
| Курьер | адрес, назначенный через `assignCourier` | принять, начать и завершить доставку |

## Допустимые переходы

```text
Created -----> Accepted -----> InTransit -----> Delivered
   |               |
   +---------------+---------> Cancelled
```

Числовые значения `enum`, которые может показать Remix:

| Число | Состояние |
|---:|---|
| 0 | `Created` |
| 1 | `Accepted` |
| 2 | `InTransit` |
| 3 | `Delivered` |
| 4 | `Cancelled` |
